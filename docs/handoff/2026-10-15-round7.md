### What step 1 did

- **The configs.** Each `_s1desc` config is its district's round-6 `_keptland` config with four
  keys changed: `data_load.s1_orbit` ASCENDING to DESCENDING, `name`, `description`, and
  `export.drive_folder` (`fmu_exports_kept_land_s1desc`). Everything the round-6 runs had stays:
  kept land only, the soft ceiling, the fit without the small stands, the distance cap, the boxes,
  k = 5. The orbit moves the fingerprint.
- **The reuse plan.** The orbit is a new kind of difference for the reuse tool: `data_load` reads
  it, but only to load the radar collection, `s1_collection`, which it passes on and does not
  cache, while the asset it caches, the S2 composite, is built without it; `features_radar` is
  the only stage that reads the collection. `RECOMPUTE_VIA_CONTEXT` names that path, and a test
  checks it in the code (the key's name in no upstream module but `data_load.py`; there only in
  `_load_s1` and the stage's metadata; `_load_s1`'s one use the `s1_collection` output; only
  `features_radar` reads it). So the S2 composite is copied and the radar features computed.
  The dry run (offline):
