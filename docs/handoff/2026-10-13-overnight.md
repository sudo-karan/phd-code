## Background

- The pipeline draws forest stands in Earth Engine. It masks out non-habitat, loads imagery,
  computes features (optical, radar, structure, static), segments with SNIC, merges superpixels
  into stands, gives each stand a type with k-means, computes metrics and exports. There are two
  versions ("arms"): hand-crafted features and AlphaEarth embeddings. The sites are Sanjay Van
  (primary) and Odisha, which has field data: 274 plots in four districts, 267 of them inside the
  mapped village forests, in 20 villages.
- Phase 3 (PR #41) found that at both stand sizes (stands up to 10 ha and up to 3 ha), the stands
  cannot be told from chance against the field data.
- The supervisor's direction, all binding:

     null comes after them, only as the significance test behind an established statistic.
  2. Transparency: every step of the pipeline shown on its own, not just the land-cover mask, in
     the outputs now and in a UI later.
  3. ETH canopy height stays in the pipeline.
  4. He asked to see the land-cover masked output. That is the first deliverable tonight.

### 6. Evaluation metrics, offline only

- Write `docs/evaluation_metrics.md`, organised by what reference data a site has:
  - **Field plots with measurements** (Odisha):
    - Rand index / adjusted Rand index on categories. Drawing: field type against stand.
      Labelling: field type against stand type, within district.
    - At the pair level, the pipeline makes one of three claims about each pair of plots: same
      stand; different stand but same type; different type. Compare that claim with the field
      difference between the two plots on four structural measurements (height, crown cover,
      trunk area, tree count; robust-scaled as in `odisha_phase3_0_field_structure_types.py`).
      Make the comparison within distance bands and within villages: nearby plots are alike
      whatever the map says, and pooling villages creates differences that vanish inside each one.
    - Established tests for this: Mantel and partial Mantel (distance held fixed), ANOSIM,
      PERMANOVA. The rotation null comes last, as a significance test only.
    - Types are fitted separately per district, so a type number means a different forest in each
      district. Compare types only within a district, and record this as an open design question.
  - **Reference polygons** (compartment maps, FSI polygons): standard segmentation-accuracy
    measures, such as over- and under-segmentation and boundary match.
  - **No reference data**: how alike plots are within a stand compared with across stands, on
    layers the pipeline did not use. Explained variance is already in `metrics.py`. Global Score is
    in the spec but not implemented.
  - For each metric: what it measures, why it is here, papers with DOIs verified against Crossref,
    and the strength of support (used / recommended / shown better).
- Candidate references. These are unverified starting points: verify each one before citing it,
  and drop any that don't check out:
  - Rand 1971 (Rand index)
  - Hubert & Arabie 1985 (adjusted Rand index)
  - Mantel 1967 (Mantel test)
  - Smouse, Long & Sokal 1986 (partial Mantel)
  - Guillot & Rousset 2013 (limits of Mantel tests with spatial data)
  - Clarke 1993 (ANOSIM)
  - Anderson 2001 (PERMANOVA)
  - Harms et al. 2001 (torus-translation test, the closest published relative of the rotation null)
  - Johnson & Xie 2011 (Global Score)
  - Clinton et al. 2010 (segmentation accuracy against reference polygons)
- Implement a general module, `src/fmu/evaluation/`. No Odisha-specific code. Inputs: stand ids,
  stand types, plot coordinates and attributes, optional village or group ids, and optional
  reference polygons.
- Validate on synthetic data with known answers:
  - each metric recovers a planted stand map;
  - power: how often each test detects planted agreement of different strengths, with numbers
    like Odisha's (267 plots in 20 villages, unevenly filled).
- **Do not run the new metrics on real Odisha or Sanjay Van data.** The supervisor approves the
  list first. Prepare the run script only.
- Note: some descriptive pair comparisons were run on Odisha data in chat. They are why the
  distance-band and within-village controls are in the list. Do not use them to choose any metric.
- Done when: the document is drafted, the module and its tests pass, and the synthetic validation
  results are committed.
