## Task 2: the method changes

Each change sits behind a config setting that is **off by default**. Off, the code does exactly
what it does now, and the `_r9` configs and their keys stay as they are. The R3 configs (Task 3)
switch every one of them on. The rules apply to both arms alike.

1. **k-means outside Earth Engine (A2, B15).** Fit k-means on the stand table with
   scikit-learn, on the rows the fit uses today: one row per stand, the stands below the minimum
   size left out of the fit and given the nearest centre. Use the declared preprocessing,
   median/IQR scaling with exact quartiles. Use k-means++ with 25 starts, seed 42, and keep the
   start with the lowest within-cluster sum of squares. Write each stand's type back to the image
   by its stand label. The `k_elbow` step already reads these rows client-side; reuse it. Record
   in the clustering metadata:
   - the best start's within-cluster sum of squares,
   - how much the 25 starts agree with each other (the median and lowest pairwise ARI). This is
     a diagnostic of the clustering, not a field score.
2. **The log rule (A3, B12, Q8).** Log only right-skewed bands (skew above the threshold), as
   `log1p((x − min) / IQR)`. Take the minimum over every stand, fitted or not, so the log is
   defined for all of them; a band whose IQR is 0 is dropped as constant before this. Do not
   transform left-skewed bands. Never log or skew-test the sine
   and cosine of an angle (the NDVI phase, aspect), and scale each such pair with one shared
   spread, so the circle is not stretched. Record each band's skew before and after.
3. **`ndvi_mean` as the window mean (C9, Q31 (c)).** The band is the fitted curve's mean over
   the dates window, whatever `time_reference` is. Compute it analytically; for a whole number
   of years it is a + f × the window's middle. This is in `features_optical`, a Locked module.
4. **The elbow in the fit's own space (A7).** With the setting on, the `k_elbow` step runs on the
   same rows and in the same scaled space as the fit (k 2 to 12, 25 starts, seed 42, no plot
   read). Its cache key already leaves out `k`, so choosing k later does not recompute it. Add a
   pass that stops after it (`--through k_elbow` in the runner and the wrapper): it runs the
   merge and the elbow, and submits no clustering, profiling or export. Also save each run's fit
   rows, after preprocessing and keyed by stand label, as a result file (off git if over 5 MB),
   so a fit at another k can later be scored offline with no Earth Engine.

Then the declarations, **committed before any R3 run.** Add a short amendment to the kept-land
declaration:
