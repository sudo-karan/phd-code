# Module status

Tracks each module's state. Not started · Under review · Locked.

A module is **Locked** when the code is read, has tests (fast + live where applicable), is documented, and is part of the smoke test. A change to a Locked module needs an entry in `docs/decisions.yaml`. `utils/provenance.py` and the evaluation package (`src/fmu/evaluation/`) are **Under review** until they meet these criteria.

`docs/decisions.yaml` is the decision register: one entry per decision with its alternatives, rationale, evidence and papers; `tests/test_decisions_register.py` checks its structure. The decisions behind the additions marked "Since v1.2.0" in the table below are recorded there under ids starting `night-`, with status `pending` until reviewed. Each addition adds outputs, properties or manifest keys; none changes a value an existing output held.

**Build order is not runtime order.** This file is build order, what was worked on in which order. Runtime order (what runs in a pipeline run) lives in `docs/current_flow.md`.

Pipeline is at v1.2.0 with all 13 runtime stages implemented and tested.

**v1.2.0 is a reframing, not an increment: SNIC + merge produces the stand, and
clustering is demoted to attaching a type label to a finished one.** It adds the
`merge` stage, makes the SNIC band stack config-driven, stops holding
segmentation identical across arms (that was called the experiment's control and
was in fact the flaw — it never put the delineation question to the embedding),
fits k-means on every stand rather than a pixel sample, adds stand-geometry and
held-out R² metrics, derives the `reduceConnectedComponents` cap instead of
hand-setting it, and keys cache assets on config *content* rather than name.

v1.1.0 extended the export stage with vector outputs (per mentor request:
vectorized stands with per-stand attributes), added masking source toggles, and
made the harmonic-regression reference epoch configurable. Module 13 (custom CSV
hook) is deferred; no current use case.

## Field validation (Odisha)

Not a pipeline module, so it has no row above, but it is where the method is tested against
ground data. Scripts and results live in `odisha_script/`; each phase has a write-up that leads
with its answer:

- `odisha_script/PHASE1_STATUS.md` -- do the satellite features track the field measurements?
- `odisha_script/PHASE2_STATUS.md` -- do stands (up to 10 ha) group plots that are alike on the ground?
- `odisha_script/PHASE3_STATUS.md` -- the same question at 10 ha and at the 2-3 ha stand size the
  supervisor asked for, scored for how stands are drawn and how they are labelled, with field forest
  types built from structure.

Phase 3 changed no pipeline module: it added configs and the scripts and results under `odisha_script/` only.

## Evaluation (offline, general)

Status: **Under review** (row `evaluation/` in the table above). Not a pipeline stage and not run on any real site: the list of metrics in `docs/evaluation_metrics.md` is for approval first. No Earth Engine, no site-specific code.

- `src/fmu/evaluation/`: `agreement` (Rand and adjusted Rand index), `pairs` (pair comparison inside villages and distance bands), `permutation` (Mantel, partial Mantel, ANOSIM, PERMANOVA, permutation nulls, the test driver, Holm), `spatial_null` (rotation null, torus translation; they return relabelled plots, never a score), `segmentation_accuracy` (over- and under-segmentation, boundary match), `unsupervised` (explained variance, area-weighted variance, Moran's I, Global Score), `synthetic` (planted data with known answers), `_common` (shared helpers). Tests: `tests/test_evaluation_*.py`.
- `scripts/evaluation_synthetic_validation.py` checks the methods on planted data and writes `docs/evaluation/synthetic_validation.md` and `.csv`. `docs/evaluation/rotation_size_followup.md` is the declared follow-up on the rotation null.
- `scripts/run_evaluation.py` applies the metrics to one site's reference data; it refuses to run without `--predeclared <file>`.

## Scripts that read a run (not pipeline modules)

- `scripts/inspect_merge.py`: merge summary, threshold calibration, stand sizes and per-stand provenance. Read-only by default. Tests in `tests/test_inspect_merge.py`.
- `scripts/transparency_masking.py`: the land-cover mask of any config as maps, rasters and numbers, in `docs/transparency/<config>/`. Read-only on Earth Engine. `odisha_script/odisha_transparency_masking.py` is the Odisha wrapper (field plots as points, one config per district).
- `scripts/compare_cached_assets.py` (cached assets of two configs, pixel for pixel; read-only on Earth Engine) and `scripts/compare_stand_runs.py` (two exported stand layers; offline). `odisha_script/odisha_repro_compare.py` applies the second to one Odisha arm and re-scores it. `odisha_script/run_passes_safely.py` runs `run_config_passes.sh` one pass at a time, never while earlier tasks are queued. Results: `docs/reproducibility.md`.
- `scripts/segmentation_route.py` (which inputs a run segmented on, cached features or live ones, read from its manifest; offline) and `scripts/snic_cached_vs_live.py` (SNIC from a config's cached features, from live ones, and from live ones on the pixel grid of the cache, compared with each other and with the cached superpixels; read-only on Earth Engine). Tests in `tests/test_segmentation_route.py` and `tests/test_snic_cached_vs_live.py`. Results: `docs/reproducibility.md`, "Superpixels depend on whether the features were cached when SNIC ran".
